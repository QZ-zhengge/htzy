# HTZY_v2.0 总体重构方案

> 版本：v0.2（已确认）｜ 日期：2026-09-04
> 状态：用户已确认，进入P0实施阶段
> 前置：本机 MySQL root 密码已确认；Node.js 18+、CMake 3.20+、MSVC（VS 2022+）为开发环境。

---

## 1. 目标与硬性约束（来自用户）

| # | 约束 | 说明 |
|---|------|------|
| 1 | 纯 C++ 项目 | Python 后端（Flask 路由、AI 客户端、面试业务闭环）全部用 C++20 重写，运行时不再依赖 Python |
| 2 | VS可编译运行 | 开发期间保证 VS 2022+ 可直接 Debug/Release 编译运行测试；一键部署暂缓，等产品做完后再考虑 |
| 3 | 数据库全重设计 | 本机 MySQL 为空库（root/qige_060803）；旧三套库表全部作废，重写统一 schema，服务启动时幂等自建 |
| 4 | 敏感信息外置 | 所有 key / 数据库账号密码 / 端口一律进配置文件（gitignore），代码零硬编码 |
| 5 | 前端 Vue 工程化 | 弃用原 HTML/CSS/JS，前端为独立 Vue 工程（组件化 + 路由 + 状态管理），构建产物由 C++ 服务托管 |
| 6 | 岗位数据来自爬虫 | 岗位数据由"大学生就业服务平台"独立爬虫项目写入；本工程只交付**一个爬虫连接配置文件**（库名 + 爬虫专用账号 + 密码 + 表名），并建设最小权限账号 |
| 7 | 日志系统 | 前期控制台输出即可；后期必须有带时间戳的独立日志文件（级别：debug/info/warn/error），设计时预留接口 |

### 日志系统设计（约束 7）
- 当前阶段（开发期）：所有日志走 `std::cout` / `std::cerr`，带 `[时间戳] [级别] [模块]` 前缀。
- 后期切换：只需在 config 中配置 `log_file` 路径，Logger 自动追加输出到文件（同步双写或仅文件），代码无需改动。
- 实现：`common/logger.h` 单文件，提供 `LOG_INFO(...)` / `LOG_ERROR(...)` 宏，支持流式输出。

### 爬虫交付物（约束 6 的最终产出）
- 单独配置文件：`config/crawler_db.conf`（gitignore，不入库）。
- 内容：数据库名、爬虫专用用户名、随机生成密码、岗位表名。
- 数据库账号权限：仅对**岗位表一个表**拥有 SELECT / INSERT / UPDATE / DELETE，其余库表无任何权限。
- 该文件由用户拷给爬虫项目使用，爬虫适配由用户自行完成。

## 2. 总体架构

```
                        ┌─────────────────────────────────────────┐
                        │           浏览器 (用户)                  │
                        └───────────────┬─────────────────────────┘
                                        │ HTTP/JSON (REST, JWT Bearer)
                                        ▼
                        ┌─────────────────────────────────────────┐
                        │      HTZY_v2.0 C++ 后端 (单进程/单端口)  │
                        │  httplib 静态托管 frontend/dist + /api/* │
                        ├─────────────────────────────────────────┤
                        │  auth ▸ users ▸ resumes                 │
                        │  interviews ▸ questions ▸ answers       │
                        │  results ▸ dashboard(stats/radar/trend) │
                        │  jobs(查询/搜索/筛选/详情)               │
                        │  ai/ (DeepSeek REST + 讯飞图像 WS)       │
                        │  db/ (连接池 + 参数化SQL + 自动建表)      │
                        └───┬──────────────┬───────────────┬──────┘
                            │              │               │
                   ┌────────▼──────┐ ┌─────▼──────────┐ ┌─▼────────────────┐
                   │ MySQL (统一)   │ │ DeepSeek API   │ │ 讯飞星火 WS(图像) │
                   │ 库 htzy        │ │ 简历/出题/评分  │ │ 摄像头微表情实时  │
                   │ 表见 §4        │ │ /报告          │ │ 分析             │
                   └────────────────┘ └────────────────┘ └──────────────────┘
                            ▲
                    大学生就业服务平台爬虫(独立项目, 仅写 jobs 表)
```

说明：
- **单服务模型**：C++ 后端同时承担 REST API 与前端静态资源托管（沿用 httplib 的 mount point 能力），Vue 构建产物 `dist` 拷入运行目录。
- **认证**：统一采用 JWT（HS256，密钥来自配置文件），替换旧的 Flask session 与自造 token 两套并存。
- **语音链路（重构取舍）**：旧语音评分依赖浏览器 Web Speech 转写文本 + 文本大模型四维评分。v2.0 保持同一用户可感知流程：浏览器转写 → 提交文本 → C++ 调 DeepSeek `analyze_voice` 返回 普通话/稳定性/清晰度/语言组织 四维分入库。旧 `text_analysis.py`（讯飞 v1.1 WS）为死代码，不迁移。

## 4. 数据库设计（统一库 `htzy`，utf8mb4，表名/列名全英文）

> 原则：参数化 SQL、英文列名、时间统一 DATETIME、评分 DECIMAL(5,2)、删除用逻辑标记或级联（按业务）。

```sql
CREATE DATABASE IF NOT EXISTS htzy CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- 用户
CREATE TABLE IF NOT EXISTS users (
  id            INT AUTO_INCREMENT PRIMARY KEY,
  username      VARCHAR(50)  NOT NULL UNIQUE,
  password_hash VARCHAR(128) NOT NULL,            -- sha256(salt+password)，salt 存同表
  salt          VARCHAR(32)  NOT NULL,
  email         VARCHAR(100) NOT NULL UNIQUE,
  phone         VARCHAR(20)  NULL,
  avatar        VARCHAR(255) NULL,
  bio           TEXT         NULL,
  role          ENUM('user','admin') DEFAULT 'user',
  created_at    DATETIME DEFAULT CURRENT_TIMESTAMP,
  last_login    DATETIME NULL,
  interview_count INT DEFAULT 0
) ENGINE=InnoDB;

-- 简历（文件记录；.txt/.pdf/.doc/.docx，纯文本内容供 AI 分析）
CREATE TABLE IF NOT EXISTS resumes (
  id          INT AUTO_INCREMENT PRIMARY KEY,
  user_id     INT NOT NULL,
  file_path   VARCHAR(255) NOT NULL,
  content     MEDIUMTEXT NULL,                    -- 文本抽取结果
  upload_time DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  INDEX idx_user (user_id)
) ENGINE=InnoDB;

-- 面试
CREATE TABLE IF NOT EXISTS interviews (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  user_id      INT NOT NULL,
  job_position VARCHAR(100) NOT NULL,
  status       ENUM('pending','in_progress','completed','aborted') DEFAULT 'pending',
  start_time   DATETIME NULL,
  end_time     DATETIME NULL,
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
  INDEX idx_user_status (user_id, status)
) ENGINE=InnoDB;

-- 面试题目
CREATE TABLE IF NOT EXISTS interview_questions (
  id             INT AUTO_INCREMENT PRIMARY KEY,
  interview_id   INT NOT NULL,
  question_text  TEXT NOT NULL,
  question_type  VARCHAR(50) NOT NULL,            -- technical/behavioral/situational/case_study/culture_fit
  difficulty     TINYINT NOT NULL,                -- 1-5
  order_number   INT NOT NULL,
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  INDEX idx_interview (interview_id, order_number)
) ENGINE=InnoDB;

-- 作答
CREATE TABLE IF NOT EXISTS interview_answers (
  id           INT AUTO_INCREMENT PRIMARY KEY,
  interview_id INT NOT NULL,
  question_id  INT NOT NULL,
  answer_text  MEDIUMTEXT NULL,
  start_time   DATETIME NULL,
  end_time     DATETIME NULL,
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  FOREIGN KEY (question_id)  REFERENCES interview_questions(id) ON DELETE CASCADE,
  UNIQUE KEY uq_question (question_id)
) ENGINE=InnoDB;

-- 面试结果（总分 = 专业0.4 + 语言0.3 + 表达0.3）
CREATE TABLE IF NOT EXISTS interview_results (
  id                INT AUTO_INCREMENT PRIMARY KEY,
  interview_id      INT NOT NULL,
  professional_score DECIMAL(5,2) NOT NULL DEFAULT 0,
  language_score    DECIMAL(5,2) NOT NULL DEFAULT 0,
  expression_score  DECIMAL(5,2) NOT NULL DEFAULT 0,
  overall_score     DECIMAL(5,2) NOT NULL DEFAULT 0,
  report            MEDIUMTEXT NULL,              -- AI 报告 JSON 字符串
  created_at        DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  UNIQUE KEY uq_interview (interview_id)
) ENGINE=InnoDB;

-- 微表情逐帧分析（原中文列名废用 → 英文）
CREATE TABLE IF NOT EXISTS facial_analysis (
  id              INT AUTO_INCREMENT PRIMARY KEY,
  interview_id    INT NOT NULL,
  frame_number    INT NOT NULL,
  stress_level    DECIMAL(5,2) NOT NULL DEFAULT 0,   -- 紧张程度
  dressing_neat   DECIMAL(5,2) NOT NULL DEFAULT 0,   -- 着装整洁度
  eye_contact     DECIMAL(5,2) NOT NULL DEFAULT 0,   -- 眼神接触
  facial_express  DECIMAL(5,2) NOT NULL DEFAULT 0,   -- 面部表情
  created_at      DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  INDEX idx_interview (interview_id)
) ENGINE=InnoDB;

-- 语音四维评分（浏览器转写文本 → DeepSeek 评分）
CREATE TABLE IF NOT EXISTS voice_analysis (
  id             INT AUTO_INCREMENT PRIMARY KEY,
  interview_id   INT NOT NULL,
  mandarin       DECIMAL(5,2) NOT NULL DEFAULT 0,   -- 普通话水平
  voice_stability DECIMAL(5,2) NOT NULL DEFAULT 0,  -- 声音稳定性
  clarity        DECIMAL(5,2) NOT NULL DEFAULT 0,   -- 回答清晰度
  organization   DECIMAL(5,2) NOT NULL DEFAULT 0,   -- 语言组织
  created_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
  FOREIGN KEY (interview_id) REFERENCES interviews(id) ON DELETE CASCADE,
  INDEX idx_interview (interview_id)
) ENGINE=InnoDB;
```

### 4.1 岗位表（爬虫目标表，仅此表开放给爬虫账号）

```sql
CREATE TABLE IF NOT EXISTS jobs (
  id            BIGINT AUTO_INCREMENT PRIMARY KEY,
  job_title     VARCHAR(200) NOT NULL,            -- 岗位名称
  company_name  VARCHAR(200) NOT NULL,            -- 单位/公司名称
  location      VARCHAR(100) NULL,                -- 工作地点（城市/地区文本）
  province      VARCHAR(50)  NULL,                -- 省（便于地区筛选）
  city          VARCHAR(50)  NULL,                -- 市（便于地区筛选）
  salary_min    INT NULL,                         -- 最低月薪(元)，无法解析为 NULL
  salary_max    INT NULL,                         -- 最高月薪(元)
  salary_text   VARCHAR(100) NULL,                -- 原始薪资文本（如"面议"）
  education     VARCHAR(50) NULL,                 -- 学历要求：本科/硕士/不限…
  experience    VARCHAR(50) NULL,                 -- 经验要求：应届/1-3年…
  industry      VARCHAR(100) NULL,                -- 行业
  job_tags      JSON NULL,                        -- 标签数组 ["C++","后端"]
  job_desc      MEDIUMTEXT NULL,                  -- 岗位描述/要求原文
  source_url    VARCHAR(500) NOT NULL,            -- 来源页URL
  source_platform VARCHAR(100) DEFAULT '大学生就业服务平台',
  publish_date  DATE NULL,                        -- 平台发布日期（可空）
  crawl_time    DATETIME DEFAULT CURRENT_TIMESTAMP, -- 爬取时间
  UNIQUE KEY uq_source_url (source_url(255)),     -- URL 去重（幂等爬取）
  INDEX idx_city (city),
  INDEX idx_industry (industry),
  INDEX idx_edu_exp (education, experience),
  FULLTEXT KEY ft_desc (job_title, job_desc)      -- 搜索（可选用）
) ENGINE=InnoDB;
```

- 爬虫账号（由本工程 root 建库阶段自动创建）：
  - 用户名：`htzy_crawler`，主机 `localhost`（如需跨机器抓取，实施时可再授予 `%`）。
  - 权限：仅 `htzy.jobs` 的 `SELECT, INSERT, UPDATE, DELETE`。
  - 密码：请使用本地配置
- 去重策略：以 `source_url` 唯一键做幂等 upsert，爬虫重复抓取不产生脏数据。

## 6. 一键部署 `run HTZY` 设计

脚本：仓库根 `run`（bash，Linux/macOS）与 `run.bat`（Windows）。兼容两种调用：`./run HTZY`（按项目名部署）与 `./run start` 等价；另支持子命令。

子命令：
| 命令 | 行为 |
|------|------|
| `run HTZY` / `run start` | 完整部署并启动：检查依赖 → 编译后端 → 构建前端 → 初始化/迁移数据库 → 后台启动服务 → 健康检查 |
| `run stop` / `run restart` | 停止 / 重启 |
| `run status` | 查看运行状态与端口 |
| `run init-db` | 仅执行建库建表 + 创建爬虫账号（幂等），生成/更新 `crawler_db.conf` |
| `run build` | 仅编译前后端 |
| `run logs` | 查看服务日志 |

流程细节：
1. **环境检查**：cmake / 编译器（MSVC cl 或 g++）／node+npm ／mysql 客户端或连接可达；缺失给出明确指引后退出。
2. **后端编译**：CMake configure + build（Windows 用预设 `x64-release`）。
3. **前端构建**：`npm ci && npm run build` → 产物复制到后端静态目录。
4. **数据库**：用配置文件中的管理员账号（首启时若 `app.conf` 未建库凭据，则提示输入 root 一次性建库）执行 schema 迁移（C++ 内嵌迁移器，幂等）；同时 `CREATE USER IF NOT EXISTS htzy_crawler` + `GRANT` + 随机密码，写入 `crawler_db.conf`。
5. **启动**：后台运行可执行文件（Windows 用 start /b，Linux 用 nohup），`logs/` 收集输出；curl 健康检查 `/api/health` 通过即提示访问地址。
6. 每次部署前自动 `git pull`? —— **不做**，部署仅基于本地代码，保持行为可预期。

> 备注：若希望命令字面为 `run HTZY`，可在 PATH 中软链/复制 `run`；脚本支持把第一个参数 `HTZY` 视为项目名直接部署。

## 7. REST API 设计（前缀 `/api`，统一 JWT）

| 方法/路径 | 鉴权 | 说明 |
|---|---|---|
| POST /api/auth/register | 否 | 注册 → 返回 token |
| POST /api/auth/login | 否 | 登录 → 返回 token |
| POST /api/auth/logout | 是 | 登出 |
| GET  /api/user/profile ｜ PUT | 是 | 用户资料 |
| POST/GET /api/resumes ｜ GET/DELETE /api/resumes/{id} | 是 | 简历上传/列表/详情/删除 |
| POST /api/interviews | 是 | 创建面试（内部：AI 简历分析→出题入库） |
| GET  /api/interviews ｜ /{id} | 是 | 列表/详情 |
| POST /api/interviews/{id}/start ｜ /end | 是 | 开始/结束（结束=汇总评分+AI 报告，防重入） |
| GET  /api/interviews/{id}/questions | 是 | 取题 |
| POST /api/interviews/{id}/answers | 是 | 提交作答 |
| POST /api/interviews/{id}/analyze_face | 是 | 摄像头帧 → 讯飞图像 WS → 微表情 4 维入库存档 |
| POST /api/interviews/{id}/analyze_voice | 是 | 转写文本 → DeepSeek 4 维评分入库存档 |
| GET  /api/interviews/{id}/results | 是 | 结果 + AI 报告 |
| GET  /api/dashboard/stats ｜ /radar ｜ /trend | 是 | 用户中心统计/雷达/趋势（**真实计算**，废弃 C++ 硬编码演示值） |
| GET  /api/jobs?keyword=&city=&industry=&page= | 否 | 岗位分页搜索（读 jobs 表） |
| GET  /api/jobs/{id} | 否 | 岗位详情 |
| GET  /api/health | 否 | 健康检查 |

并发与稳定性设计（吸取旧项目教训）：
- 面试帧分析**串行化/限流**（每面试单飞队列），防止 WS 并发请求竞争与连接堆积。
- `/end` 加防重入锁（沿用旧 0xC0000374 修复思路，在 C++ 中用 per-interview 状态机保证）。
- AI JSON 解析失败一律重试一次 + 默认兜底，报告生成失败不阻断主流程。
- 全链路参数化 SQL；密码 sha256+salt 存储；JWT 过期 24h。
